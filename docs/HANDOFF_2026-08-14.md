# JobPilot 对话交接摘要

更新时间：2026-08-14（Asia/Shanghai）

## 1. 项目目标

JobPilot 是一个面向真实用户的 AI 求职工具。用户通过共享访问密码进入站点，再使用邮箱登录；上传并确认简历后，可实时搜索匹配岗位，或向指定招聘邮箱投递。系统只自动投递到页面公开展示、可核验且明确用于招聘的邮箱，不用虚拟岗位或虚构联系方式补足结果。

## 2. 当前已完成状态

### 登录与发信

- 站点入口由共享访问密码隔离；具体密码不写入交接文档。
- 登录页顺序为：普通邮箱直接登录在上，Gmail 一键登录在下。
- Gmail 用户通过 OAuth 登录并使用 Gmail API 发信。
- 非 Gmail 用户无需配置 QQ、163 或 SMTP，使用平台域名统一代发。
- 平台代发设置 `Reply-To` 为用户登录邮箱，企业直接回复时会回到用户邮箱。
- 平台代发会 BCC 一份完整邮件及附件给用户；Gmail API 发信不重复 BCC，避免与“已发送”重复。
- 已删除 QQ/163 SMTP 主机、端口、授权码表单及对应设置 API；旧数据库字段未删除，但运行时不读取或返回。
- 支持用户手动填写一个指定招聘邮箱进行投递。
- 邮件正文会根据岗位和候选人信息生成基本礼貌、自我介绍和来意说明。

### 简历与岗位搜索

- 支持 PDF、DOCX、TXT 简历上传、解析和人工确认。
- 匹配搜索走 OpenAI Responses 风格的 `/responses` 接口，并启用 `web_search` 工具。
- 当前非敏感模型配置：
  - Base URL：`https://kuaipao.pro/v1`
  - Model：`gpt-5.6-sol`
  - 配置思考程度：`light`
  - 实际请求兼容映射：`light -> reasoning.effort: low`
- API Key 只存在本地 `.env`，不得在新聊天中读取、显示、复制或写入文档。
- 该 Key 曾在聊天消息中明文出现，应尽快在服务商后台轮换，随后只更新本地 `.env`。
- 搜索先执行一次综合查询；不足 5 个时再执行聚焦补充查询，达到至少 5 个即停止；单批最多保留 10 个真实结果（单次综合查询可以直接返回超过 5 个）。
- 来源范围包括雇主招聘页、政府或学校公开招聘公告、正规招聘平台的具体岗位详情页；拒绝搜索结果页、通用首页、匿名转载和平台客服联系方式。
- 仅保留目标城市和真实来源，排除已展示 URL、已出现的岗位指纹、`example.com` 和重复岗位。
- 公开招聘邮箱是自动邮件投递的必要条件；只有官方申请链接、表单或门户的真实岗位会保留为 `official_apply`，展示给用户手动申请，不会自动发邮件。
- 模型引用兼容两种形态：消息 annotations，以及 `web_search_call.action` 中的 `open_page.url` / `site:<host>` 查询。
- 可通过 `JOBPILOT_VERIFY_URLS=1` 对未被模型显式引用的公开岗位 URL 做附加存在性校验；实现包含私网/回环地址拦截，防止 SSRF。
- 搜索失败时返回空结果和明确警告，不使用演示岗位兜底。

### 前端

- 全站已由深色主题改为“明亮液态玻璃”设计：珍珠白/浅灰背景、深灰文字、克制蓝色强调。
- 玻璃效果只用于登录容器、顶部进度、底部导航、搜索状态和确认操作条；内容区保持平整清晰。
- 登录页保留精简三步说明：“登录邮箱 -> 上传确认简历 -> 搜索岗位或指定邮箱投递”。
- 主要界面集中在 `src/components/JobPilot.tsx`，包括 onboarding、dashboard、matches、详情、确认、applications、profile。
- 已做 390x844 手机和 1280x800 桌面入口页视觉检查；截图在 `output/playwright/`。
- 因登录后页面可能显示真实简历和个人数据，交接过程中不要截图、打印或泄露这些内容。

## 3. 最近问题与修复

### 搜索弹窗显示“模型搜索返回 502”

根因不是简历或筛选规则，而是模型配置：

1. 历史上曾把模型名错误地写成缺少前缀的 `5.6-sol`，当时 `/responses` 返回 502；当前 kuaipao 配置使用正确的完整标识 `gpt-5.6-sol`。
2. 中转服务不接受字面值 `reasoning.effort: light`，会返回 400；不带该参数和使用 `low` 都经最小诊断请求验证为 200。
3. 已修正模型名，并在 `src/infrastructure/job-search.ts` 中把配置值 `light` 映射为请求值 `low`。

修复后已重新构建并重启服务，但尚未使用真实用户简历重新跑完整岗位搜索流程。下一窗口如要验证，应由用户主动触发，避免擅自使用或输出个人简历内容。
